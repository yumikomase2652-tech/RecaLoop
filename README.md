# RecaLoop

教材の問題番号と自作暗記カードを登録し、4段階評価で復習日を管理する個人用Webアプリです。

## 今回の範囲

- Supabase Authによるメール認証
- メール確認コールバックとパスワード再設定
- 教材デッキと無限階層の章・節・問題番号
- 柔軟な教材CSVインポートとプレビュー
- 暗記カード、自作カード、CSVインポート
- `again / hard / good / easy`評価
- チェック、復習予定、評価履歴
- 一覧評価と1問ずつの学習モード
- 教材デッキ・暗記カードの限定リンク共有と独立コピー
- 投稿申請、運営承認、承認済みコンテンツだけの公開ライブラリ
- 承認済み公開版と編集版を分離するJSONスナップショット
- EXP、レベル、自動獲得称号
- デッキ完走称号と公開ライブラリの匿名獲得数
- 匿名統計による教材ランキング
- 1問ずつ学習モードの自動セッション記録
- 評価を変えずに保存できるチェックトグル
- PWA manifestとアプリアイコン

先生生徒機能、課題配布、高度なSNS、APKG、R2、コインUIは含みません。

## 起動

```bash
npm install
cp .env.example .env.local
npm run dev
```

Supabase未設定時は `/dashboard` がデモデータで動きます。

## Supabase

新しいSupabaseプロジェクトのSQL Editorで、番号順にすべて実行します。

```text
supabase/migrations/0001_recaloop.sql
supabase/migrations/0002_add_card_id.sql
supabase/migrations/0003_sharing.sql
supabase/migrations/0004_release_library.sql
supabase/migrations/0005_growth_rankings_snapshots.sql
```

既存の個人用MVPデータベースには、未適用の番号から実行してください。旧版の先生生徒テーブルが存在するDB向けの移行ではないため、開発中の旧DBはリセットするか、新規プロジェクトを使用してください。

`.env.local`:

```bash
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
```

全学習テーブルでRLSを有効にし、ログインユーザー本人が所有するデータだけを操作できます。評価保存は`review_target` RPCでstate更新とattempt履歴作成を一度に行います。評価なしでチェックだけを保存した場合は、既存の評価・復習日・復習回数を維持したまま`unknown_flag`だけを更新し、`action = 'check'`の履歴を追加します。

公開状態は次のように管理します。

- `private`: 所有者だけが利用
- `unlisted`: URLを知る人だけが閲覧・コピー可能
- `submitted`: 運営の審査待ち
- `approved`: 公開ライブラリへ掲載
- `rejected`: 却下理由を表示し、修正後に再申請可能

共有・公開されるのは教材の章構造、問題番号、短いメモ、または暗記カード内容です。評価state、attempt履歴、チェック、復習状態は公開もコピーもされません。「コピーして使う」は認証済みユーザー用RPCで新しい所有データを作成します。

承認時の内容は`published_snapshot`へ保存します。承認後に所有者が編集しても公開版は変化しません。「公開版を更新申請」で現在の編集内容を`pending_snapshot`へ固定し、運営承認時だけ`published_snapshot`を差し替えます。更新申請が却下されても既存の公開版は維持されます。

## EXP・レベル・称号

EXPは学習実績として累積し、レベルと称号の判定に使います。消費機能はありません。

- 教材item評価: +5 EXP
- 暗記カード評価: +3 EXP
- 2回目以降の復習完了: +5 EXP
- デッキ初回完走: +50 EXP
- 前日から学習を継続: 1日1回 +10 EXP

評価とEXP台帳更新は同じ`review_target`トランザクションで処理します。チェックだけの保存ではEXPを付与しません。レベルは`1 + floor(total_exp / 100)`で自動計算します。

累計EXP称号：

- 100: 見習い学習者
- 500: 学び始めた者
- 1,000: 継続の達人
- 2,000: 努力の証
- 5,000: 知識の収集家
- 10,000: 探究者
- 20,000: 学者
- 40,000: 賢者

デッキを初めて完走すると、「デッキ名 完走」というシンプルな称号を獲得します。称号は`titles`と`user_titles`で複数保持でき、プロフィールの`equipped_title_id`で1つだけ装備できます。

## ランキング

`/rankings`ではapprovedコンテンツだけを、人気・完走率・継続率・最近のコピーで表示します。進捗統計はコピー後の独立デッキから匿名集計し、サンプル数3未満では平均進捗率・完走率・継続率を返しません。個人名や個人別進捗は公開しません。

管理者を設定するには、対象ユーザーが一度ログインして`profiles`が作成された後、Supabase SQL Editorで次を実行します。メールアドレスからAuthユーザーを確認し、意図したユーザーだけを管理者にしてください。

```sql
update public.profiles
set is_admin = true
where id = 'AUTH_USERS画面で確認したUUID';
```

管理画面は`/admin/submissions`です。サーバー側の画面ガードに加え、管理RPCとRLSでも`is_admin`を確認します。

Supabase AuthenticationのURL Configurationには、ローカル開発時は`http://localhost:3000/auth/callback`、本番では`https://YOUR_DOMAIN/auth/callback`と`https://YOUR_DOMAIN/auth/update-password`をRedirect URLとして登録してください。Vercelには上記2つの公開環境変数を設定し、デプロイ後に共有リンクが本番ドメインで生成されることを確認します。

## CSV

教材CSVは左から右を大階層から小階層として解釈し、最後の非空セルを問題itemにします。

```csv
第1章 物質の構成,第1回 原子,エクササイズ,問1
第1章 物質の構成,第1回 原子,エクササイズ,問2
```

暗記カードCSVは`card_id,front,back,memo`形式です。`card_id`と`memo`は省略できます。

```csv
card_id,front,back,memo
001,apple,りんご,名詞
002,run,走る,動詞
```

どちらも保存前にitem数、階層、重複候補を確認できます。

## 復習間隔

復習計算は`lib/fsrs.ts`の`calculateNextReview`に集約しています。

- `again`: 今日
- `hard`: 1日後
- `good`: 3日後
- `easy`: 7日後

## 著作権への配慮

教材デッキでは教材名、章・節、問題番号、自分用の短いメモだけを扱います。教材本文、問題文、解答全文を入力するUIはありません。暗記カードはユーザー自身が作成した`front / back / memo`を保存します。

## PWA・ネイティブ化

`app/manifest.ts`、`public/icon.svg`、最小Service Workerを用意し、production環境で登録してstandalone表示に対応します。Service Workerは現時点ではキャッシュを持たず、認証データや画面を古い状態で表示しません。画面とSupabaseアクセスはブラウザ標準APIだけに依存しているため、将来は同じWebビルドをCapacitorでラップできます。Expoへ移行する場合も、`lib/recaloop-data.ts`のデータ操作境界を再利用しやすい構成です。

## 収益化メモ

現時点では課金・広告・コインを実装しません。検討順は次の通りです。

1. 広告なしプレミアム
2. 学習テーマ・プロフィール表現
3. ライブラリ便利機能
4. 出版社・塾との公式デッキ提携
5. 将来的なコイン

EXPは学習実績として維持します。将来コインを導入する場合も、購入・報酬・残高をEXPとは別テーブル、別UI、別規約で扱います。
