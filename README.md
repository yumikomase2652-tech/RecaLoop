# RecaLoop

階層つきデッキを作成し、4段階評価で復習日を管理する個人用Webアプリです。

## 今回の範囲

- Supabase Authによるメール認証
- メール確認コールバックとパスワード再設定
- 学習デッキと無限階層の章・節・問題番号・カード
- 柔軟なCSVインポートとプレビュー
- 自作カード、CSVインポート、画像・音声メディア添付
- `again / hard / good / easy`評価
- チェック、復習予定、評価履歴
- 一覧評価と1問ずつの学習モード
- `.recaloop`ファイルによるデッキ書き出し・読み込み
- IndexedDBによる画像・音声メディアの端末内保存
- EXP、レベル、自動獲得称号
- デッキ完走称号
- 1問ずつ学習モードの自動セッション記録
- 評価を変えずに保存できるチェックトグル
- 先生/生徒ロール、招待コード連携、課題配布
- 生徒詳細、課題進捗、課題編集、teacher viewer mode
- 選択モードからの学習計画作成とカレンダー調整
- 所有者確認付きのデッキ削除
- スマホ375px幅での日付入力レイアウト調整
- PWA manifestとアプリアイコン

公開ライブラリ、SNS、APKG、R2、課金、広告、コインUIは現時点では画面から外しています。

## 起動

```bash
npm install
cp .env.example .env.local
npm run dev
```

RecaLoopはSupabaseの実データのみを表示します。Supabase環境変数が未設定、または取得に失敗した場合は組み込みデータへ切り替えず、画面にエラーを表示します。

## Supabase

新しいSupabaseプロジェクトのSQL Editorで、番号順にすべて実行します。

```text
supabase/migrations/0001_recaloop.sql
supabase/migrations/0002_add_card_id.sql
supabase/migrations/0003_sharing.sql
supabase/migrations/0004_release_library.sql
supabase/migrations/0005_growth_rankings_snapshots.sql
supabase/migrations/0006_onboarding_learning_stats.sql
supabase/migrations/0007_streak_titles_ui_cleanup.sql
supabase/migrations/0008_teacher_assignments_plans.sql
supabase/migrations/0009_recover_profiles_rls.sql
supabase/migrations/0010_library_updates_independent_copies.sql
supabase/migrations/0011_teacher_viewer_mode.sql
supabase/migrations/0012_teacher_viewer_assignments.sql
supabase/migrations/0013_owned_delete_and_student_detail_layout.sql
```

既存の個人用MVPデータベースには、未適用の番号から実行してください。旧版の先生生徒テーブルが存在するDB向けの移行ではないため、開発中の旧DBはリセットするか、新規プロジェクトを使用してください。

`.env.local`:

```bash
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
```

全学習テーブルでRLSを有効にし、ログインユーザー本人が所有するデータだけを操作できます。評価保存は`review_target` RPCでstate更新とattempt履歴作成を一度に行います。評価なしでチェックだけを保存した場合は、既存の評価・復習日・復習回数を維持したまま`unknown_flag`だけを更新し、`action = 'check'`の履歴を追加します。

デッキ配布は`.recaloop`ファイルの書き出し・読み込みを基本にします。評価state、attempt履歴、チェック、復習状態は`.recaloop`には含めません。

デッキ削除は`delete_owned_content` RPCで所有者を確認してから実行します。他ユーザーのデッキや過去の学習履歴は削除されません。学習デッキ一覧と復習対象はログイン中ユーザーの`user_id`で絞り込みます。

## 先生・生徒・課題

`profiles.role`は次の3状態です。

- `none`: 個人利用
- `student`: 課題メニューを表示
- `teacher`: 生徒メニューを表示

先生は生徒画面で招待コードを発行します。生徒は課題画面でコードを入力し、`teacher_student_links.status = 'active'`になると担当教師が表示されます。招待コードは更新可能で、古いコードは無効化されます。連携解除は先生側・生徒側の両方から行えます。

先生の生徒詳細は次に絞っています。

- 概要
- 課題進捗
- 課題作成
- 課題一覧

細かい学習状況は「この生徒の画面を見る」からteacher viewer modeで確認します。viewer mode中は画面上部に「○○さんの画面を表示中」を固定表示し、先生権限のまま生徒本人のホーム、復習、デッキ、カレンダー、課題、設定表示を確認できます。連携済み生徒以外はviewer modeで閲覧できません。

課題はデッキ内のカードを対象に作成します。課題詳細では複数カードに評価やチェックを付け、まとめて保存できます。先生は課題名、期限、対象カードの追加・削除、課題削除を行えます。

## 学習計画とカレンダー

デッキ詳細の選択モードでitem/cardを選び、「計画作成」を押すと開始日・終了日を入力するモーダルが開きます。未完了項目はデッキ内の自然順を保ったまま、期間内の日付へ均等に連続割り当てします。

例: 10問を5日に配分する場合は、1日目に問1・問2、2日目に問3・問4、という順で割り当てます。

カレンダー画面では月表示で予定枚数を確認できます。日付を開くと予定item/cardを選択し、スケジュールから削除、または日付選択モーダルで他の日へ移動できます。

スマホ幅では日付入力を含むフォームを横並びにしません。課題作成、課題編集、計画作成、カレンダー移動のすべてで、`DateInput`と親フォームに`width: 100%`、`max-width: 100%`、`min-width: 0`を適用し、375px幅でカード外にはみ出さないようにしています。

## EXP・レベル・称号

EXPは学習実績として累積し、レベルと称号の判定に使います。消費機能はありません。

- デッキ内カード評価: +5 EXP
- 2回目以降の復習完了: +5 EXP
- デッキ初回完走: +50 EXP
- 前日から学習を継続: 1日1回 +10 EXP

評価とEXP台帳更新は同じ`review_target`トランザクションで処理します。チェックだけの保存ではEXPを付与しません。レベルは`1 + floor(total_exp / 100)`で自動計算します。

累計EXP称号：

- 100: 見習い学習者
- 500: 学び始めた者
- 1,000: 継続の達人
- 2,000: 努力の証
- 5,000: 知識の収集家
- 10,000: 探究者
- 20,000: 学者
- 40,000: 賢者

デッキを初めて完走すると、「デッキ名」そのものを称号として獲得します。表示側に「デッキ完走称号」の見出しを付けるため、称号名には「完走」を重ねません。称号は`titles`と`user_titles`で複数保持でき、プロフィールの`equipped_title_id`で1つだけ装備できます。

## 認証URL

Supabase AuthenticationのURL Configurationには、ローカル開発時は`http://localhost:3000/auth/callback`、本番では`https://YOUR_DOMAIN/auth/callback`と`https://YOUR_DOMAIN/auth/update-password`をRedirect URLとして登録してください。Vercelには上記2つの公開環境変数を設定します。

## CSV

CSVは左から右を大階層から小階層として解釈し、最後の列を問題番号またはカード本文として扱います。階層は最大6階層程度を想定しています。

基本形式:

```csv
階層,階層,階層,階層,階層,問題番号,表面;裏面
数学,数I,二次関数,基本,例題,1,問題文;解答
```

表裏を持たない問題番号だけのCSVも扱えます。

```csv
数学,数I,二次関数,基本,例題,1,001
```

従来の`card_id,front,back,memo`形式も維持しています。

## 初回設定と学習統計

初回ログインでは学年と志望校の設定が完了するまでアプリ本体を表示しません。志望校候補は文部科学省「規模別大学一覧表（令和6年5月1日現在）」掲載の816大学と「未定」を収録しています。

学年は日本の学年度に合わせて4月を境に自動更新し、設定画面から手動修正もできます。ホームの90日ヒートマップはデッキ内カードの評価、復習完了、学習セッションを日別に集計します。

```csv
第1章 物質の構成,第1回 原子,エクササイズ,問1
第1章 物質の構成,第1回 原子,エクササイズ,問2
```

どちらも保存前にitem数、階層、重複候補を確認できます。

## メディアと.recaloop

カードには表面・裏面それぞれに画像または音声を添付できます。メディア本体はSupabaseには保存せず、ブラウザのIndexedDBに端末内保存します。カード側は`front_media_ids` / `back_media_ids`で内部メディアIDを参照します。

`.recaloop`ファイルは通常のZIPファイルです。手作業で作る場合も、次の構成のZIPを作成して拡張子を`.recaloop`に変更すれば読み込めます。書き出し時もWindows/macOSで展開できる通常ZIPとして生成します。

```text
deck.json
cards.csv
media/
  0001.jpeg
  0002.png
  0003.mp3
```

`deck.json`には`deckId`、`title`、`description`、`createdAt`、`updatedAt`、`appVersion`、`reviewMode`を保存します。説明、版、年度などは`description`に自由に書きます。

`cards.csv`では本文中に`[ファイル名]`でメディアを参照します。推奨形式は、最大6階層、問題番号、`cardId`、本文の順です。

```csv
数学,数I,二次関数,基本,例題,1,card_001,このグラフを見て答えよ[0006.jpeg];頂点は(1, -4)
英語,単語,基本,,,1,card_002,apple[0007.mp3];りんご
```

手作業で作りやすいように、`cardId`なしの形式も読み込めます。その場合はRecaLoopが`deckId`と行内容から安定した`cardId`を生成します。

```csv
数学,数I,二次関数,基本,例題,1,このグラフを見て答えよ[0006.jpeg];頂点は(1, -4)
```

読み込み時は`deckId`と`cardId`を維持します。同じ`deckId`のデッキが既にある場合は重複作成せず、既存デッキを更新します。同じ`cardId`のカードが既にある場合は重複追加せず、内容とメディア参照を更新します。`cardId`がない既存カードは、階層、表面、裏面、順番が一致する場合に`cardId`を付与して移行します。既存の学習履歴、評価、チェック、復習状態は削除しません。

### deckId / cardId

- `deckId`: デッキ全体を識別する固定ID
- `cardId`: カード1枚を識別する固定ID
- 同じ元デッキから配布されたデータは、端末やユーザーが違っても同じ`deckId` / `cardId`を共有します。
- タイトル、本文、階層、順番を変更しても、既存カードの`cardId`は変更しません。
- 学習履歴はSupabase側に残し、`.recaloop`再読み込みでは履歴を消さずにカード内容だけを更新します。

## 復習間隔

復習設定はデッキごとに`ライト` / `デフォルト`を選べます。回答ボタンはAnkiに近い4段階です。

- `again`: もう一回
- `hard`: 難しい
- `good`: 正解
- `easy`: 簡単

新規カードの学習ステップ目安:

- デフォルト: `3m 30m`
- ライト: `30s 10m`

ステップ終了後の最初の復習間隔は1日、「簡単」は4日を目安に表示します。現在のDB保存は日付単位の復習予定を維持し、将来の分単位スケジューリングへ移行しやすいように`review_mode`を保存しています。

## 著作権への配慮

デッキでは章・節、問題番号、自分用の短いメモ、またはユーザー自身が作成した`front / back / memo`を保存します。教材本文、問題文、解答全文の転載を促すUIは置きません。

## PWA・ネイティブ化

`app/manifest.ts`、`public/icon.svg`、最小Service Workerを用意し、production環境で登録してstandalone表示に対応します。Service Workerは現時点ではキャッシュを持たず、認証データや画面を古い状態で表示しません。画面とSupabaseアクセスはブラウザ標準APIだけに依存しているため、将来は同じWebビルドをCapacitorでラップできます。Expoへ移行する場合も、`lib/recaloop-data.ts`のデータ操作境界を再利用しやすい構成です。

## 収益化メモ

現時点では課金・広告・コインを実装しません。検討順は次の通りです。

1. 広告なしプレミアム
2. 学習テーマ・プロフィール表現
3. `.recaloop`配布・読み込みの便利機能
4. 出版社・塾との公式デッキ提携
5. 将来的なコイン

EXPは学習実績として維持します。将来コインを導入する場合も、購入・報酬・残高をEXPとは別テーブル、別UI、別規約で扱います。
